# Decks mats, presets and zones

Status: immutable mat/preset records and generic-zone implementation with server-side drop effects, 2026-09-21; visual zone editor contract added 2026-09-23.

Presets pin immutable template/mat versions and generic configuration. They never contain old session cards, random results or private hand contents. Authenticated owners create immutable mat versions and table presets through `/api/mats` and `/api/presets`; `/api/mats-and-presets` lists only the caller's records. The `configure_table` action validates an owned preset, persists its immutable reference and configuration, and copies its named zones into the lobby session. `create_zone`/`update_zone`/`delete_zone` persist host-owned zones with finite rectangle coordinates, positive width/height, bounded priority and allowlisted behavior. Zone configuration mutations are allowed only while the session is in the lobby; starting freezes them until the host resets the session to the lobby. Every mutation is submitted with the current expected session revision and targets a zone in the same session.

The table UI draws zones as labeled, non-interactive rectangular overlays behind cards and piles. During the lobby, a host with effective `zone.manage` may add a zone and edit or delete an existing zone. The editor exposes name, rectangle geometry, priority, and effect; `fan` additionally accepts degrees from 1 through 180. Deletion requires confirmation. Non-hosts, denied hosts, and active/ended sessions do not receive mutation controls. Zone names and settings contain no card or participant data.

Snapshots expose the selected configuration and authorized zones to table members. Supported drop effects are `none`, `face_up`, `face_down`, `stack`, `align`, `fan`, and `owner_private`; they are applied server-side when a card is placed on the table, moved as a group, or played from a hand. A zone has a name, geometry and explicit priority. If a card center is inside multiple zones, the highest priority wins, then the smallest area; equal-ranked conflicting effects are rejected rather than guessed. `owner_private` assigns the placing actor as the only card-definition viewer. Spatial zones never replace logical card containment. Zone effects are applied in the same durable action transaction and projected through the viewer's privacy rules.
